### 阶段 1：服务端权威游戏循环

1. **房间生命周期**
   - 创建房间时锁定地图和模式；加入已有房间时使用房间实际配置。
   - 限制真人数量，清理断线玩家，空房间停止 tick 任务并从内存删除。
   - 使用安全的房间码、昵称清洗和消息类型白名单。

2. **输入和移动**
   - 只接受归一化的移动向量、瞄准坐标、开火、蓄力和能力请求。
   - 服务端计算速度、冲刺、墙体碰撞、地图边界、出生点和无敌时间。
   - 客户端只发送输入，不发送位置、生命值、弹药或击杀结果。
   - 右键跳跃闪避、护盾和修复由服务端校验冷却与能量；初始能量为 10，服务端自动回复，跳跃期间短暂免伤，护盾将单次伤害限制到 10；每 200 未消费战绩提供 1 个技能点，可用于生命、速度或武器强化，每项最多三级。

3. **武器系统**
   - 每个武器定义统一的 `kind`、伤害、冷却、速度、寿命、弹匣、备弹、装填时间、爆炸半径、散射角和追踪参数。
   - 实现直射、散射、反弹、抛物线爆炸、火焰短程、白色贯穿弹、黄色追踪弹、虫群追踪、治疗光束和能量光束/能量球连锁爆炸等行为。
   - 处理射速限制、切枪延迟、弹匣消耗、装填中断、墙体遮挡、爆炸范围和伤害衰减。
   - 地图武器箱由服务端生成和回收，拾取后武器归玩家所有，弹药状态随玩家同步。

4. **可见性和掩体**
   - 服务端决定草丛/掩体中的隐藏状态，隐藏玩家不能被普通客户端直接读出。
   - 追踪武器只能锁定服务端判定为可见的目标；墙体阻挡射线时不产生锁定或伤害。
   - 允许本地玩家看到自身、必要的命中反馈和合理的环境提示。

5. **模式规则**
   - 普通混战：击杀得分并在延迟后复活。
   - 感染者模式：感染队伍、转化或复活规则与队伍状态同步。
   - 队伍积分：队伍伤害保护、队伍分数和胜利条件。
   - 夺旗：两面旗帜、拾取、携带、掉落、返回和得分。
   - 五命决斗：生命数耗尽后退出本局，最后存活者获胜。
   - 感染生存：真人和感染者的合作/对抗胜利条件。

6. **机器人**
   - 机器人使用同一套服务端移动、瞄准、射击和伤害逻辑。
   - 机器人不能读取草丛隐藏目标；会在墙体附近重新选路，并定期换位、射击和复活。
   - 普通/队伍模式使用 4 个机器人；感染生存使用 18 个感染者；决斗模式严格保持 1v1 真人房间。

完成标准：两个或更多独立 WebSocket 客户端能看到同一房间、同一地图、同一玩家移动和投射物；位置由服务端收敛，玩家断线后不会留在排行榜或碰撞体中。

### 阶段 2：前端战斗体验和原创视觉

1. 保留俯视角、固定比例 Canvas 和清晰的 HUD 层次，使用 Morrow Fields 的苔木、果园和赤叶遗迹主题及四套原创角色外观。
2. 参考正式游戏的像素大厅和模式卡片，采用跟随玩家的缩放镜头；小地图同时显示全图和当前视野框。大厅使用六种原创像素模式卡、像素边框、硬阴影、复古色板和双栏布局，保持 Morrow Fields 原创标题与图标。
3. 为每种武器绘制独立的像素弹体、拖尾、枪口闪光、爆炸和命中特效；颜色只用于识别，不复用原游戏贴图。
4. 地图绘制顺序固定为底色、纹理、掩体、装饰、墙体、旗帜、拾取物、投射物、玩家、HUD，避免遮挡层级错误。
5. 桌面端支持 WASD/方向键、鼠标瞄准、按住左键连射、右键跳跃闪避、`1–0/N/M/H/J/L` 切枪、`R` 装填、`F` 蓄力、`Y` 第二射击模式、`Q/E` 技能；点选升级后按 `Space` 确认，`V/X/C` 可直接购买。
6. 移动端保留虚拟移动区和右侧瞄准/射击区，按钮与小地图不覆盖核心战场。
7. 房间码、邀请链接、开放房间列表、聊天、击杀播报、比分和模式结束提示必须来自服务端状态，不使用客户端猜测。

完成标准：新玩家不看代码即可知道如何加入房间、移动、射击、拾取和切换武器；刷新或从邀请链接进入后可以重新加入同一房间。游戏镜头跟随本地角色，瞄准仍由服务端接收世界坐标，小地图显示全图与当前视野。

### 阶段 3：联机和回归验证

编写可重复的验证脚本，至少覆盖以下场景：

5. **地图检查**：三张地图的墙体碰撞、掩体隐藏、出生点和拾取点均不重叠在墙内。

## 四、已知边界和风险

- “样子几乎接近”按俯视角、像素化、实时房间、武器栏、地图遮挡和战斗节奏来实现；人物造型、地图布局、名称、颜色和素材保持原创。
- 房间状态目前以内存保存，进程重启会清空房间；没有账号、持久化战绩、匹配服务和反作弊系统。
- 公网部署依赖用户自己的云平台账户和网络环境；未提供真实 URL 前只能验证本地和局域网。
- 真实多人质量还取决于网络延迟、代理是否支持 WebSocket、浏览器刷新和设备性能；v62 主机负载模拟的 10 人 LAN 接口状态间隔 P95 为 `12.82ms`、最大 `20.87ms`，但同机模拟不能覆盖 Wi‑Fi、交换机、路由和远端浏览器延迟，实体设备和长时间稳定性仍未验证。

## 五、每次改动后的固定流程

1. 先读当前状态和失败日志，确定问题属于协议、模拟、渲染还是部署。
2. 修改最小范围的源文件，并同步更新协议或说明。
3. 运行构建、编译和相关联机测试；涉及 UI 时运行浏览器检查。
4. 查看真实输出、截图和监听端口，确认结果不是旧进程、旧 `dist` 或示例数据。
5. 最后更新 README 和本计划中的完成状态，再向用户报告已验证的范围和仍未验证的范围。
