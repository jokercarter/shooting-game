# Morrow Fields vs slay.one · 差距盘点与改进优先级

> 口径：以当前 `main`（PR #7 之后）为准。slay.one 侧只描述**公开可见的玩法与交互**，不涉及它的代码或素材。
> 结论先行，每条都给「现状 → 差距 → 怎么改 → 优先级」。

---

## 0. 一句话结论

**玩法骨架已经够用，真正拉开差距的是三件事：没有账号与持久化、没有新手路径、客户端还在每帧重画整个世界。** 前两个决定留存，第三个决定能不能上 24 人房和低端机。

### 最该先做的五件事
| # | 事项 | 为什么现在做 | 预估 |
|---|---|---|---|
| 1 | 账号 + 战绩持久化（哪怕只存昵称/等级/胜负） | 现在房间全在内存，进程一重启玩家所有进度归零，留不住人 | 3–5 天 |
| 2 | 新手引导（30 秒三屏 + 训练场） | 新玩家落地就被打死，没有第二次机会 | 2–3 天 |
| 3 | 地面 / 障碍离屏缓存 | 每帧重画 100px 网格与全部 props，是低端机掉帧的主因 | 2 天 |
| 4 | 弹道碰撞空间网格 | 现在是 O(弹道×玩家)，24 人房是最大瓶颈 | 3 天 |
| 5 | CI（pytest + Playwright） | 现在靠本地跑，回归靠人肉 | 1 天 |

## 1. 玩法机制

| 项 | 现状 | slay.one | 差距 | 改进建议 | 优先级 |
|---|---|---|---|---|---|
| 成长曲线 | 等级 28、8 项属性、每级 2 点 | 等级解锁武器 + 技能点 | **武器全程全给**，成长只体现在数值，缺少"解锁新东西"的期待感 | 武器按等级分段解锁（Lv3/6/10/14 各开一把），已解锁的保留；属性点不变 | P1 |
| 局的概念 | 房间常驻，达成条件后重置 | 同样常驻 | 无差距 | — | — |
| 模式深度 | 6 模式（FFA/TDM/CTF/感染/1v1/合作） | 模式更多，但有重复 | 数量够，**深度不足**：都是"杀人或占点" | 给每图加 1 个中立机制（可破坏掩体 / 定时补给空投 / 中央增益点） | P2 |
| 地形交互 | 草丛隐蔽、传送门、桥 | 同样以掩体为主 | 无差距，隐蔽规则我们更严谨（对称） | — | — |
| 节奏 | 复活 6s、满血重生 | 复活更快（约 3s） | 6s 在 20 人房里偏长，死亡惩罚重 | 做 A/B：FFA 用 4s，1v1 用 6s；用 `mode` 配置而不是全局常量 | P2 |
| 反作弊 | 服务端权威，客户端只发输入 | 同样 | 无差距 | 补一条：输入频率上限 + 位移速度校验（现在靠 `PLAYER_SPEED_SCALE`） | P2 |
| 武器差异 | 14 把，按 kind 分 6 族 | 更多，且每把有明确定位 | **定位重叠**：多把武器数值接近，玩家没有"为什么换这把"的理由 | 给每把写一句定位（射程/爆发/控场），按定位调 1–2 个参数，不要全面重做 | P1 |

## 2. 核心功能

| 项 | 现状 | 差距 | 改进建议 | 优先级 |
|---|---|---|---|---|
| 账号体系 | 无，昵称即身份 | **最大缺口**：换设备即换人，无法沉淀 | 轻量账号：设备 ID + 可选邮箱绑定；只存 `player_id / 昵称 / 等级 / 总击杀 / 总场次` | P0 |
| 数据持久化 | `rooms: dict` 全内存，`backend/migrations/versions` 为空 | 重启即清零，无法做排行榜 | SQLite（单机足够）+ 一张 `profiles` 表 + 一张 `matches` 表；先不做复杂 schema | P0 |
| 匹配 | 房间列表 + 房间码 | 无快速匹配、无按等级/延迟匹配 | 加一个 `/api/arena/quick-match`：优先同模式、延迟 <80ms、人数未满的房间，否则新建 | P1 |
| 组队 | 无，靠房间码 | 好友一起玩要手动报码 | 生成可分享邀请链接 `?room=ABC123`，点开自动填码（成本极低） | P1 |
| 排行榜 | 无 | 无长期目标 | 用持久化的 `matches` 表出「今日击杀榜 / 赛季等级榜」，先做日榜 | P1 |
| 新手引导 | 无，落地即战场 | 首局留存杀手 | 30 秒三屏图文（移动/瞄准/技能）+ 可选训练场（3 个木桩 + 无限弹药） | P0 |
| 设置 | 只有低特效/小地图/武器栏/聊天/音量开关 | 无按键重绑定、无画质档位、无灵敏度 | 加「按键绑定」与「鼠标灵敏度」两页；画质改成 低/中/高 三档，映射到现有的 `displaySettings` | P1 |
| 观战 / 回放 | 有观战、240 帧短回放可导出 | 回放不可分享、无时间轴拖动？ | 回放加时间轴拖动 + 生成分享链接（上传到对象存储成本高，可先导出文件） | P2 |
| 社交 | 大厅聊天（全局） | 无好友/私聊/举报 | 先加「最近同局玩家」列表 + 一键邀请；举报入口做成表单 | P2 |
| 移动端 | 有触屏双摇杆逻辑，无双摇杆 UI | 触屏可玩但不可发现 | 加可视摇杆 + 开火键 + 技能键，落地页标注「支持手机」 | P1 |
| 国际化 | 中英混排硬编码 | 无法出海 | 抽 `i18n` 字典（先中/英），文案集中到一个文件 | P2 |

## 3. 代码架构

| 项 | 现状 | 风险 | 改进建议 | 优先级 |
|---|---|---|---|---|
| 后端组织 | `backend/arena.py` 单文件 2890 行：常量、数据类、规则、机器人、序列化、广播、房间循环全在一起 | 改一处要读全文件；新人上手成本高；合并冲突频繁 | 按职责拆 5 个模块：`rules.py`（伤害/移动/技能）、`bots.py`、`protocol.py`（view/序列化）、`rooms.py`（生命周期）、`arena.py`（路由与入口）。**纯搬移，不改逻辑**，一次拆一个模块 | P1 |
| 前端组织 | `public/arena/game.js` 单文件 2800 行，无模块、无类型 | 同上；且无法做 tree-shaking / 按需加载 | 拆 ES modules：`net / state / render / hud / input / art`；先加 JSDoc 类型，再考虑 TS | P1 |
| 持久层 | 无 | 见 §2 | 同 §2 | P0 |
| 视图层 | 两套广播路径（<8 人逐 viewer / ≥8 人共享 + private 补丁） | 逻辑正确但**两条路径容易改漏** | 抽出 `build_view(room, viewer)` 单一出口，两条路径只决定「传给谁」，不决定「怎么算」 | P2 |
| 测试 | pytest 128 例（单元为主）+ Playwright 11 例 | 缺集成/负载/长稳测试 | 补：① 24 人房 60 秒长稳（已有 `tools/verify_arena_load.py`，接进 CI）；② 断线重连集成测试 | P1 |
| CI/CD | 无 GitHub Actions | 回归靠人肉，PR 合并无门禁 | 加 `.github/workflows/ci.yml`：pytest + Playwright（headless）+ `node --check` | P0 |
| 构建 | `build.mjs` 只做 copy | 无压缩/无哈希/无缓存策略；`dist` 不入库导致「改了没生效」 | 加 esbuild 打包 + 内容哈希；静态资源加 `Cache-Control: immutable`；开发环境直接服务 `public/`，消除 build 依赖 | P2 |
| 可观测性 | 只有 uvicorn 日志 | 线上出问题只能猜 | 加结构化日志（房间创建/销毁、tick 超时、掉线）+ `/api/arena/metrics` 暴露房间数/人数/tick 耗时 | P1 |
| 配置 | 常量硬编码在 `arena.py` | 调平衡要改代码 | 抽 `config.py` 或环境变量：复活时间、XP 系数、房间容量 | P2 |

## 4. 性能表现

| 项 | 现状 | 瓶颈点 | 改进建议 | 优先级 |
|---|---|---|---|---|
| 弹道碰撞 | `for projectile … for target in room.players.values()`，O(弹道×玩家) | 24 人 × 200 弹道 ≈ 4800 次/帧 | 玩家做均匀网格（100px 格），弹道只测所在格及邻格；AABB 先行剔除 | P0 |
| 状态广播 | 20Hz；大房间共享快照 + private 补丁；弹道全量下发 | 带宽随弹道数线性增长 | 弹道改为「出生/消亡事件 + 客户端预测」，或对弹道做 2 帧差分 | P1 |
| 客户端重绘 | 每帧 `drawGrid()` 重画 100px 网格 + 草叶 + 细点，`drawProps()` 重画全部树/箱 | 这是低端机掉帧主因（实测本机 21.9 FPS） | **地面与静态障碍离屏 canvas 缓存**（按镜头分块，9 块循环复用），只在镜头移动超过 1 格时重绘 | P0 |
| 抽象层 | Canvas 2D | 无 WebGL，大量 `fillRect` 小图元 | 中期可换 PixiJS/WebGL；短期先靠离屏缓存 + 合批（同色块合并路径） | P1 |
| 粒子 | 数组 push/splice，上限 520 | GC 抖动 | 改对象池（预分配 520 个，标记复用） | P2 |
| 自适应降级 | `lowEffects` 手动开关 + 宽度 <760 自动紧凑 | 无帧率驱动 | 加自动降级：连续 3 秒 <40 FPS 自动关粒子/降草叶密度，并在 UI 提示可手动恢复 | P2 |
| 网络 | WebSocket + JSON | JSON 体积大 | 中期换二进制（MessagePack），短期先去掉 `null` 字段与重复键 | P2 |
| 服务端 tick | 按人数自适应 tick 间隔（`_room_tick_rate`） | 合理 | 保持；补 tick 耗时打点 | P1 |

**量化现状**：单测 128 通过；Playwright 11 例中 10 过，`ten-player crowd` 的 55 FPS 断言在本机（有常驻 Chrome）实测 21.9 FPS 失败 —— 这条恰恰说明性能是真实短板，不该当成 flaky 忽略。

## 5. 用户体验

| 项 | 现状 | 问题 | 改进建议 | 优先级 |
|---|---|---|---|---|
| 首屏信息量 | 一屏 20+ 控件（模式 6、地图 3、房间、聊天、网络卡） | 新玩家不知道先点哪 | 分两步：首屏只留「昵称 + 快速开始 + 房间码」；模式/地图收进「自定义」 | P0 |
| 键位可发现性 | 只在页脚 8px 小字 | 多数人不知道有冲刺/技能 | 首局叠加半透明键位提示，5 秒后淡出；设置里可重看 | P0 |
| 死亡反馈 | 倒计时 + 观战切换 | 不知道自己被谁杀的 | 加「击杀者 + 武器 + 距离」的死亡回执（3 行，带方向箭头） | P1 |
| 受击方向 | 只有屏幕红闪 | 不知道子弹从哪来 | 加屏幕边缘方向指示（4 个扇区，0.6s 衰减） | P1 |
| 命中反馈 | 伤害数字 + 抖动 + 音效 | 手感已不错 | 补「命中标记」准星反馈（X 形，120ms） | P2 |
| 音频 | WebAudio 合成音，无音乐 | 氛围弱 | 加 1 条循环环境底噪 + 菜单 BGM（可关闭） | P2 |
| 错误提示 | 断线自动重连 | 房间满/版本不符时提示不明确 | 统一 toast 文案 + 可重试按钮 | P1 |
| 无障碍 | 无 | 色盲玩家难分红绿血条 | 血条加形状区分（实心/斜纹），对比度提到 4.5:1 | P2 |
| 加载态 | 资源异步加载，无 loading | 首屏可能闪一帧空场景 | 加 300ms 内的骨架/淡入，超过 1s 显示进度 | P2 |
| 移动端 | 触屏可玩，无可视摇杆 | 不可发现 | 见 §2 | P1 |

## 6. 优先级总表

### P0（两周内，直接影响留存与可玩性）
1. 账号 + SQLite 持久化（`profiles` / `matches`）
2. 新手引导 + 训练场
3. 地面 / 静态障碍离屏缓存
4. 弹道碰撞空间网格
5. CI（pytest + Playwright + 语法检查）
6. 首屏信息减法 + 首局键位提示

### P1（一个月内，决定"能不能长期玩"）
7. 快速匹配 + 邀请链接
8. 武器按等级解锁
9. 后端拆 5 模块 / 前端拆 ES modules
10. 按键绑定 + 灵敏度 + 画质三档
11. 死亡回执 + 受击方向指示
12. 排行榜（日榜）
13. 移动端可视摇杆
14. 结构化日志 + metrics 端点

### P2（三个月内，锦上添花）
15. 每图中立机制、可破坏掩体
16. 复活时间按模式配置
17. 回放时间轴与分享
18. 音频氛围层、无障碍、i18n
19. 构建管线（esbuild + 哈希 + 缓存头）
20. 粒子对象池、自动降级、二进制协议

## 7. 建议路线图

```
第 1–2 周   P0：持久化骨架 → 新手路径 → 离屏缓存 → 碰撞网格 → CI
第 3–4 周   P1 上半：快速匹配 / 邀请链接 / 武器解锁 / 死亡回执
第 5–8 周   P1 下半：前后端拆分 / 设置页 / 排行榜 / 移动端摇杆 / 日志
第 9–12 周  P2：内容深度（中立机制）、构建管线、无障碍与音频
```

**判断依据**：P0 全部围绕「新玩家能不能留下」和「低端机能不能跑」；P1 围绕「老玩家有没有长期目标」；P2 才是体验打磨。
